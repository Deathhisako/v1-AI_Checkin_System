# 系统架构说明

## 1. 总体架构

系统采用**感知-决策-执行-自愈**的分层架构，与开题报告技术路线一致。

```
用户配置/任务编排/结果通知  ── 应用层 (app/)
        │
        ▼
  LLM语义理解/页面解析/异常诊断决策 ── 决策层 (decision/)
        │  ▲
        │  │ 诊断结果(ErrorKind → HealAction)
        ▼  │
   OCR/视觉大模型/验证码识别 ── 感知层 (perception/)
        │
        ▼
  请求构造/浏览器自动化/Cookie管理/加密适配 ── 执行层 (execution/)
        │
        ▼
  监控-诊断-决策-自愈 闭环 ── 核心 (core/self_heal.py)
```

## 2. 数据流

单次签到流程（一个平台）：

1. **感知**：平台返回 `(status_code, body)`，`ResponseParser` 解析出 `PageSignal`
   （是否需登录、是否验证码、是否成功）。
2. **决策**：`Diagnostician` 用结构化信号 + LLM 语义分类产出 `Diagnosis`
   （异常类型 + 处置动作 + 置信度）。
3. **执行**：`SelfHealEngine` 依据决策执行动作：
   - `relogin` → 刷新 Cookie（执行层 `CookieManager`）
   - `re_analyze` → 重建加密逻辑（执行层 `CryptoAdapter`）
   - `solve_captcha` → 语义验证码识别（感知层 `CaptchaSolver`）
   - `retry/wait` → 指数退避重试
   - `fallback_browser` → 降级浏览器自动化
   - `alert` → 报警人工介入
4. **自愈闭环**：最多 `max_attempts` 次，成功即返回，否则报警。

## 3. 四大痛点的自愈映射

| 异常类型 (ErrorKind) | 处置动作 (HealAction) | 自愈模块 | 说明 |
|---|---|---|---|
| `cookie_expired` | `relogin` | `execution/cookie_manager.py` | 状态码+页面语义监测，自动重登 |
| `dynamic_encryption` | `re_analyze` | `execution/crypto_adapter.py` | 检测校验失败→重建签名函数 |
| `captcha_required` | `solve_captcha` | `perception/providers.py` | 视觉大模型语义匹配 |
| `transient` | `retry` | `core/self_heal.py` | 指数退避 |
| `risk_control` | `wait`/`fallback_browser` | `core/self_heal.py` | 等待或降级 |
| `upgraded` | `re_analyze` | `execution/crypto_adapter.py` | 平台改版重析 |
| `unknown`/`need_human` | `alert` | `app/notifier.py` | 报警人工介入 |

## 4. 关键设计决策

1. **语义化而非硬编码**：所有异常用 `ErrorKind`/`HealAction` 枚举表达，
   处置逻辑由 LLM 语义分类驱动，而非写死 if-else。
2. **Provider 注入**：LLM/OCR/视觉/浏览器均可注入，默认 `mock` 可离线运行，
   真实接入只需替换 Provider，不改动核心逻辑。
3. **适配器单例**：平台适配器在 Runner 内缓存，Cookie/加密状态跨轮持久，
   模拟真实长期运行（无人值守）。
4. **分层解耦**：感知/决策/执行互不依赖，便于替换、扩展与测试。
5. **可观测**：事件总线 + 结构化日志，支持监控与实验数据采集。

## 5. 扩展点

- **新增平台**：实现 `CheckinPlatform`，用 `@register` 注册。
- **接入真实 LLM**：实现 `LLMClient`，`build_llm("custom")` 返回实例。
- **接入真实 OCR/视觉**：实现 `OCRProvider`/`VisionProvider`，配置 `ai.*_provider`。
- **部署**：对接 GitHub Actions cron 或系统任务计划，实现无人值守。
